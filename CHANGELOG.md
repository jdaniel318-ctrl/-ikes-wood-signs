# Black Flag Engine — Release Narrative

## v3.6.4 — Ready to Sail
- Final pre-development cleanup after the Engine Mark Repair.
- Removed the unused `black_flag_mark_dimensional.png` asset and its service-worker cache entry.
- Removed a stray Web3Forms debug log.
- Replaced legacy Ike-yellow browser/PWA theme colors with Dark Sky platform colors.

## v3.6.2 — Spring Cleaning

Dark Sky received a shipwide maintenance pass before new feature development. Historical release notes and validation debris were consolidated, the loose `app.js.bak` copy was removed, unused visual assets were removed from the deployable package, stale release labels were aligned, the project footer “Powered by Black Flag” text was retired in favor of the shared lower-right platform return mark, and the service worker was tightened so superseded Black Flag caches are removed during activation. No order, project, customer, owner, pricing, ledger, commissioning, or Captain workflow was intentionally redesigned.

## v3.6.1 — Harbor Repair

Restored the shared lower-right Black Flag return control after an older project-isolation CSS rule accidentally hid classes containing `black-flag`. Rebuilt the platform icon from the approved emblem crop and preserved the existing Engine PIN routing behavior.

## v3.6 — Platform Brand Rebuild

Made Black Flag the visual identity of Engine-owned surfaces instead of a decorative cue. Added the Engine Room platform lockup, consistent Black Flag instrumentation, Engine framing, a restrained persistent signature, and the shared lower-right project return mark while keeping project branding dominant.

## v3.5 — Platform Brand System

Expanded Black Flag identity through Engine-owned sections and replaced floating ENGINE return pills in project shells with the approved Black Flag mark while preserving routing IDs and behavior.

## v3.4 — Brand Identity Integration

Introduced the approved Black Flag visual assets and first restrained platform marks in the Engine, project Control Centers, Configure Engine, and return controls. Established the standing brand rule that the flag itself remains black and contrast comes from its surrounding field.

## v3.3 — Project Commissioning

Added Engine-native commissioning so a new business can be created without first hand-coding a project. New projects receive an identity, namespace, order prefix, private/unpublished state, business/product/customer-experience configuration, isolated operational collections, and audit metadata.

## v3.2.1 — Owner + Customer Device Refinement

Centralized deployment/device identity normalization, clarified authorization state, added explicit owner pause/resume audit events, and made project-only trust boundaries visible in Owner and Engine device views.

## v3.2 — Owner Access + Customer Device Hardening

Added project-bound customer-device identities, owner session audit events, pause/resume/revoke controls, shared deployment creation, and default-deny cross-project/device authority rules. The production server-authentication boundary remained explicit.

## v3.1 — Command & Navigation Refinement

Improved First Mate's Watch, moved Configure Engine and Project Control Centers into dedicated workspaces, tightened shared command controls, improved project-card scaling/filtering, and preserved project-brand isolation.

## v3.0 — Structural Milestone

Refit the original 2.9.x application into the Black Flag platform foundation: schema-v3 project envelopes, permanent namespaces, default-deny isolation metadata, central roles/permissions, lifecycle states, audit and recovery foundations, telemetry, project-scoped owner/order/customer/ledger/device operations, structural integrity checks, and First Mate's Watch. V3 also formalized the production boundary: external production identity still requires server-backed authentication and authorization.

### v3.0 build stages

Stage 1 established the hull and bulkheads: namespaces, policy, lifecycle, audit, migration, recovery, and integrity. Stage 2 wired those services into Owner, kiosk/device, order, customer, ledger, telemetry, and Captain-governance operations. Final v3.0 certification checked JavaScript syntax, duplicate IDs, critical command wiring, CSS structure, local service-worker assets, and architecture markers.

## 2.9.x lineage

The 2.9 series was the experimental shipyard where the original Ike's Wood Signs application evolved into a multi-project Engine, Pirate Mode, Captain's Quarters, deployment fleet, Owner Portal concepts, and the modern Engine Room visual system. Those historical implementation comments remain in source where they help explain compatibility layers, but v3 is the active Black Flag platform line.
