# v3.8.6 Secondary Command Bay Audit

## Mission
Carry the v3.8.5 iPad-first command language into every secondary Project Control menu without changing the underlying navigation routes.

## Changes
- Secondary command groups always occupy their own full-width row beneath primary commands.
- Secondary controls now use the same dark instrument surfaces, icon blocks, larger labels, selected-state treatment, and finger-sized targets as primary commands.
- Operate, Insight, Experience, Access, and System retain their existing route mappings.
- iPad/touch layouts receive generous grid-based command bays rather than leftover inline space.
- Two-choice groups expand to use available width.
- Phones receive a simple two-column secondary grid with a full-width group heading.

## Regression boundaries
No Project Control route names, project identity behavior, permission checks, owner authorization, Black Flag return navigation, or deployment lifecycle logic was changed in this refit.
